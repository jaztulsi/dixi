# Dixi Research (Phase 2E): methods worth trialing

Researched 2026-10-16 for Dixi, a voice-driven Electron browser. Each method below lists its source, date, claim, why it might help Dixi, expected effect, evidence strength and trial status. Primary sources (papers, official docs) were preferred. Vendor numbers are labeled as vendor-reported, and so are claims that rest on one secondary page. **Dixi's setup when this was written** (from `electron/src`):
- Speech recognition: Deepgram Flux `flux-general-en` with `eot_threshold` 0.7, `eager_eot_threshold` 0.4, `eot_timeout_ms` 1500, a single keyterm `Dixi`, and 80 ms AudioWorklet chunks.
- Language models: Groq `openai/gpt-oss-20b` as the voice model and `qwen/qwen3.8-27b` as the agent model. Requests use `response_format: json_object`, not strict schema mode.
- Page actions: a heuristic text-match clicker plus site-specific CSS selectors in `siteActions.js`, which breaks the hard-coding policy.

"Expected effect" is my estimate of the direction and rough size. It is not a measurement. Nothing here counts as adopted until it wins an A/B on dev and holds on held-out. Results, including negative ones, get appended to the per-topic tables.

**Dominant failure classes across these sources:** (1) grounding: right intent, wrong element; (2) ignored or invented constraints, including a named site being ignored; (3) falling back to keyword search; (4) loops and repeated actions; (5) filter and sort controls; (6) silent action failures nobody checks. Fixes with measured gains are better grounding (SeeAct), workflow memory (AWM, §3), planner/executor splits with replanning (Plan-and-Act, §3) and post-action verification (§3).

## Top 10 methods to trial, ranked by expected impact on Dixi's accuracy and latency

1. **Strict `json_schema` on Groq plus a span-grounded validator** (§5). An enum action, typed args, and site/query/product that must be verbatim transcript spans with no leading verb or particle. A named target must stay in the resolved set. Directly addresses the "up classroom", wrong-site and search-instead-of-act classes, and makes schema errors impossible. Both current models already support strict mode.
2. **Generic site resolution plus a learned site-search template** (§9). Learned cache → Wikidata P856 → candidate verification (DNS, title/brand match, parked-domain signals). Site search via OpenSearch, SearchAction, or a template learned from the first submitted GET form. Removes the "went to the site, then searched Google" class with no hand lists.
3. **Accessibility-first observation with textual-choice grounding** (§1-2). Role+name candidates, a lexical shortlist of about 20 in document order, the LLM picks an ID or "None". Replaces `siteActions.js` site selectors, which the hard-coding policy requires anyway, and targets the "go to purchase" class.
4. **Correct Flux eager protocol** (§4, §6). Speculative parse plus preconnect on EagerEndOfTurn, abort on TurnResumed, commit on EndOfTurn without re-parsing (the transcript is guaranteed identical). Drop the redundant 500 ms timer if it measures worse. Biggest end-of-speech-to-action latency win.
5. **One plan call, streamed deterministic execution, action-effect checks** (§3). LLMCompiler-style plan for chained commands, with an `expect` per step checked by code and bounded recovery. Fewer LLM calls, truthful status, no duplicated steps.
6. **Dynamic keyterms via `Configure` plus phonetic candidates to the parser** (§4). At most 50 terms from tabs, cache and page names, sent without commas. Top phonetic/fuzzy matches go to the parser with scores. Targets entity mishearings.
7. **Prompt layout for Groq caching and minimal output tokens** (§6). Static prefix first, gpt-oss on hot paths (qwen isn't cached and is a preview model), low reasoning, terse schema. Log `cached_tokens`.
8. **Per-domain playbooks with self-healing** (§3, AWM + Stagehand). Repeat tasks skip the LLM. Invalidate on a failed `expect`.
9. **Hedged fast-tier requests and Electron preconnect** (§6). Cuts p95 tails and the navigation handshake.
10. **Disagreement-triggered clarification and quote-verified answers** (§5, §8). k=3 parses only on low-confidence or risky commands. Ask when the semantic clusters disagree. Speak page facts only with a verified verbatim quote and show the source.

## Methods I didn't expect

- **Chrome already learns site search engines without any list.** It uses OpenSearch descriptors and a simple GET-form heuristic (one text input, no submit script, root page). Dixi can copy this to turn its first search on a site into a URL template.
- **Flux guarantees the eager transcript equals the final one** when no TurnResumed follows. Speculative parses are therefore exactly reusable, with no "did the words change" diffing needed. Setting `eot_threshold`=1.0 plus `ForceEndTurn` gives full app control of turns.
- **Deepgram keyterms with commas or weights fail silently.** On Nova-3, an over-limit mid-stream update kills transcription without an error. Both are invisible bugs a biasing feature could introduce.
- **Element order matters as much as element text** for LM agents, so a relevance-sorted DOM index can quietly hurt accuracy.
- **Groq structured outputs disable streaming.** "Strict schema" and "execute the first tool call while streaming" are mutually exclusive on Groq today. With a tiny schema the lost streaming benefit should be small, but measure it.
- **WebVoyager is easy enough that a plain Google-search agent scores 51%.** By the same logic, Dixi's search fallbacks can look like success in a lenient scoreboard. Grade structured outcomes.
- **Picovoice's free tier reportedly ended 2026-06-30, and openWakeWord's pre-trained models are non-commercial.** Only custom-trained openWakeWord models (Apache code) are a clean free path for a "Dixi" wake word.
- **Parked-domain detection** is a solved, cheap classifier problem (NDSS 2015). It's the missing guard for guessed `<brand>.com` URLs entering a learned cache.
